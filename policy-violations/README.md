# Policy Violations Output

This folder contains organized outputs from CrashLens policy violation scans.

## 📁 Folder Structure

### `reports/`
Contains **concise summary reports** in Markdown format:
- `violations-summary.md` - Default summary report (generated by `guard`)
- Custom named reports when using `--out-report`

**Best for:**
- Quick overview of violations
- CI/CD pipeline integration
- Human-readable summaries
- Executive reporting

### `traces/`
Contains **detailed analysis files** in JSON format:
- `violations-detailed.json` - Default detailed report (generated by `guard --detailed`)
- Custom named reports when using `--out-detailed`

**Best for:**
- Deep trace analysis
- Programmatic processing
- Integration with monitoring tools
- Debugging specific violations

## 🚀 Usage Examples

```bash
# Generate summary report only
crashlens guard logs.jsonl --rules policies/retry-loop-detector.yaml

# Generate both summary and detailed reports
crashlens guard logs.jsonl --rules policies/rules.yaml --detailed

# Custom output paths
crashlens guard logs.jsonl --rules my-policy.yaml \
  --out-report policy-violations/reports/audit-2025-08.md \
  --out-detailed policy-violations/traces/audit-2025-08.json

# Use custom output directory (NEW!)
crashlens guard logs.jsonl --rules policies/rules.yaml \
  --detailed --out-dir crashlens-reports/

# Force overwrite existing files (NEW!)
crashlens guard logs.jsonl --rules policies/rules.yaml \
  --detailed --out-dir audit-reports/ --force

# CI-friendly with privacy controls
crashlens guard logs.jsonl --rules policies/rules.yaml \
  --detailed --quiet --fail-on-violations --strip-pii
```

## 🗂️ Advanced Directory Options

### **--out-dir flag**
Places both reports in a single custom directory with standard filenames:
```bash
crashlens guard logs.jsonl --policy-template all --detailed --out-dir my-reports/
# Creates:
# my-reports/violations-summary.md
# my-reports/violations-detailed.json
```

### **File Collision Protection**
When files already exist, timestamps are automatically added:
```bash
# First run creates: violations-summary.md
# Second run creates: violations-summary-20250817-161723.md
# Use --force to overwrite instead of adding timestamps
```

## 🛡️ Privacy Controls

- `--strip-pii` - Removes sensitive information (emails, phone numbers, etc.)
- `--no-content` - Removes all content, keeps only metadata
- Both options clearly mark redacted content in reports

## 📊 Report Contents

### Summary Reports (`reports/`)
- Violation counts by severity
- Top violating rules
- Cost analysis by model
- Detector pattern summaries
- Actionable recommendations

### Detailed Reports (`traces/`)
- Complete trace analysis
- Violation grouping by rule and trace
- Retry/fallback pattern detection
- Full metadata and timestamps
- Cost breakdown and savings estimates
